# Приложение мастера Омкары для NetAngels

Самостоятельный сайт на Node.js + PostgreSQL. Сервер не обращается к Google Таблицам.
Исходники прежнего бота и Mini App сохранены отдельно и не изменены.

## Реализовано

- Публичные карточки ретритов и встреч; черновики видит только администратор.
- Регистрация через подтверждение почты, вход по паролю, одноразовое восстановление доступа.
- Администратором при подтверждении становится только адрес из серверной настройки OWNER_EMAIL.
- Анкета, личные записи, ограничение мест, сохранение цены на момент записи.
- Чек JPEG/PNG/PDF до 8 МБ; приватный доступ администратора, подтверждение/отклонение оплаты.
- После решения администратора или отмены заявки файл удаляется из рабочей БД. Копии провайдера могут содержать его до истечения их срока хранения.
- Повторная запись на встречу после завершения предыдущей; история записей сохраняется.
- Журнал решений администратора. Cookie HttpOnly/Secure/SameSite, CSRF, серверные права, SQL-параметры, CSP.

## NetAngels

Подтверждены: контейнер c503085, сайт master-omkara.ru, базовый тариф, Node.js 26.8.2, PostgreSQL, HTTPS.
Хостинг сам предоставляет APP_IP, APP_PORT, DB_CONNECTION_STRING. Не копировать пароль БД в браузерный код, переписку или архив.
Файлы релиза помещаются в `/home/c503085/master-omkara.ru/omkara/`, закрытый от прямой раздачи каталог.
Сервер раздаёт исключительно `public/`; .env, исходники сервера, резервные копии и БД не публикуются.

1. Распаковать подготовленный архив в корень сайта (архив содержит папку omkara).
2. В папке omkara выполнить `npm ci --omit=dev --ignore-scripts`.
3. Скопировать `.env.example` в `.env`, задать APP_ORIGIN, OWNER_EMAIL и настройки почты. APP_IP, APP_PORT и DB_CONNECTION_STRING оставить в окружении хостинга.
4. Выполнить `npm run migrate`. Скрипт создаёт пустую структуру без демонстрационных людей/мероприятий.
5. Запускать `npm start` из omkara, либо настроить APP_PATH на каталог с package.json.
6. Проверить `/healthz` и `/api/session`, затем регистрацию и доставку письма владельцу.

На NetAngels исходящий SMTP ограничен собственным шлюзом. Поддерживается `localhost:25` без логина/пароля (SMTP_HOST=localhost, SMTP_PORT=25). В MAIL_FROM используется noreply@master-omkara.ru. Фактическая доставка проверяется отдельно, принятие SMTP не равно получению письма адресатом.

## Telegram — отдельное переключение

Код нового адаптера есть, но он не включается без TELEGRAM_BOT_TOKEN и TELEGRAM_WEBHOOK_SECRET.
Старый webhook автоматически не меняется.
Новый маршрут `/telegram/webhook` проверяет заголовок X-Telegram-Bot-Api-Secret-Token и сохраняет обновление до ответа 200; отдельный обработчик повторяет доставку при сбоях.
Новый адаптер связывает подтверждённый кабинет со своим Telegram через ссылку в анкете, показывает записи командой /requests и открывает сайт. Сбор анкет и приём чеков выполняются на сайте.
Это не полный перенос старого планировщика публикаций/рассылок и всех чатовых меню. Для их сохранения потребуется отдельно адаптировать соответствующие модули; не переключать старый бот без согласования итогового поведения.

## Резервные копии и эксплуатация

`scripts/backup.sh` делает закрытый pg_dump без содержимого временных чеков и сохраняет 14 дней копий. Его нужно подключить через раздел Cron сайта. Задача не считается настроенной только от наличия скрипта.
Дополнительно нужна копия вне основного контейнера и проверка восстановления; место назначения выбирает владелец.
Проверять свободную память, баланс, SMTP, журнал ошибок и доступность сайта. Тариф увеличивать только по фактической нагрузке.
Зависимости фиксируются lock-файлами; обновления проверять до публикации.

## Проверки

`npm test` использует настоящий движок PostgreSQL в PGlite для транзакций и ограничений. Это локальная проверка логики, а не нагрузочный тест многопроцессного сервера.
`node test/preview.js` запускает одноразовую локальную БД на 127.0.0.1:3188. Preview не включается в архив публикации.
Не публиковать вымышленные мероприятия и тестовые аккаунты из preview.

## Откат первой публикации

Перед запуском сохранить штатный `app/hello.js` и текущий APP_PATH. При проблемах вернуть прежний APP_PATH/стартовый файл и перезапустить Node.js.
Новую базу при откате интерфейса не удалять. Перед откатом последующих версий учитывать совместимость схемы.
